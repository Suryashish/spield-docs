Every Spield series is its own set of contracts with its own maturity, so there is no single set of
addresses. This page lists the series that exist today. **Do not hard-code "the current series."** Pick one
by id with `@spield/sdk`, or discover them at runtime as described [below](#discovering-series-at-runtime).

## Admin and verification

- The admin of every mainnet contract is the **2-of-3 multisig** account `GDJ66WMVVH6MWBL4KORY2HOXWLY4UGFCMP64RC474LUJPQCPQUC4RUFL`: three signers of weight 1, all thresholds 2, master key weight 0.
- Each series' PT is issued by its own account, which is **locked** (no signer has any weight). The full `CODE:ISSUER` is in the tables above. Compare both parts, never the code alone.
- Each contract exposes `code_hash()` and `version()`, so you can check which build is live. See [Reading state](/docs/developers/reading-state#verifying-what-is-running).
- Maturity is **immutable**. It is set once when a series is initialized and cannot be rolled or extended.

## Discovering series at runtime

Series are short-lived and new ones appear without any change to your code. There are three ways to find them.

### 1. The SDK

```ts
import { SpieldClient, mainnet } from '@spield/sdk';

const spield = new SpieldClient({ network: mainnet() });
await spield.loadSeries();                              // adds series launched after your SDK version

spield.listSeries();                                    // every known series, newest maturity first
spield.listSeries({ status: 'live' });                  // only series you can still open positions in
spield.listSeries({ source: 'ustry', status: 'live' }); // only USTRY series
```

Each entry carries `id`, `name`, `source`, `asset`, `expiry`, `maturityDate`, `status` and
`daysToMaturity`. `listSeries()` makes no network call. `status` and `daysToMaturity` come from the clock.

### 2. The hosted, signed series lists

Spield publishes one list per network:

- `https://www.spield.live/sdk/mainnet-series.json`
- `https://www.spield.live/sdk/testnet-series.json`

Each file is `{ format, version, payload, signature }`. The `payload` is a JSON string of the series
(contract addresses, expiry, PT `code` and `issuer`), and the `signature` is a base64 **ed25519 signature over
the UTF-8 bytes of that payload string**. The SDK pins the public keys, so neither a CDN nor a cache in between can slip in a
contract address. The lists only **add** series: a series id never changes once published, and the SDK
falls back to its built-in series if the list cannot be fetched. Mainnet and testnet use separate keys.

If you do not use the SDK, you can verify a list yourself with `fetchSeriesRegistry` and
`verifySeriesRegistry` from `@spield/sdk/advanced`, together with the pinned keys (`MAINNET_REGISTRY_KEYS`,
`TESTNET_REGISTRY_KEYS`) that module exports.

<Callout type="info" title="Verify before you trust a new address">
  A list entry tells you where contracts are. If you move real funds, also read `expiry()` on the
  Yield contract and compare the PT `CODE:ISSUER` with what the contract reports through `pt_token()`.
</Callout>

### 3. The app

The Spield app lists every series for the network you are on and marks each one live or matured.
The app and the SDK's lists are maintained separately, so a series can appear in one before the other.

## Network settings

```ts
export const MAINNET = {
  rpcUrl: 'https://mainnet.sorobanrpc.com',           // community endpoint; use your own provider in production
  horizonUrl: 'https://horizon.stellar.org',
  networkPassphrase: 'Public Global Stellar Network ; September 2015',
  explorer: 'https://stellar.expert/explorer/public',
};

export const TESTNET = {
  rpcUrl: 'https://soroban-testnet.stellar.org',
  horizonUrl: 'https://horizon-testnet.stellar.org',
  networkPassphrase: 'Test SDF Network ; September 2015',
  explorer: 'https://stellar.expert/explorer/testnet',
};
```

`@spield/sdk` provides these as `mainnet()` and `testnet()`, and accepts your own RPC with
`mainnet({ rpcUrl })`.

## The retired v1 contracts

Spield's first, single-engine contract set (a wrapper, vault and market, where PT and YT were both
Stellar assets) is **retired**. It was superseded by the per-series design on this page and is not
part of the current protocol. Do not build against it. If you find an old integration or address
list that mentions a "wrapper" contract, it predates v2.

For how to call these contracts, see [Reading state](/docs/developers/reading-state),
[Integrating](/docs/developers/integrating) and [the SDK](/docs/developers/sdk).
