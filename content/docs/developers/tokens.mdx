Spield's tokens are not all the same kind of thing. PT is a classic Stellar asset, YT and SR are
contract tokens, and USTRY series have their own claim tokens. This page tells you which is which,
so you handle balances, trustlines and addresses correctly.

## At a glance (Blend series)

| Token | What it is | Trustline needed | Address you use |
| --- | --- | --- | --- |
| **USDC** | The underlying. Circle USDC on mainnet, Blend's test USDC on testnet. A classic asset with a SAC. | Yes (classic) | The USDC SAC |
| **SR** | Standardized Return. A yield-bearing share over the Strategy. A SEP-41 contract token. | No | The SR contract |
| **PT** | Principal Token. The classic asset `SPLDPT` (the code varies by series) wrapped as a SAC. | **Yes** (classic) | The PT SAC, or `CODE:ISSUER` |
| **YT** | Yield Token. The **Yield contract itself**. Not a SAC and not a classic asset. | No | The Yield contract |

All of these use **7 decimals**.

## SR (Standardized Return)

SR is what USDC becomes when you deposit it into a series. It is a share token: as the Blend position
earns, each SR is worth more USDC. The USDC value of one SR is `exchange_rate()` (12-decimal fixed point,
so `1050000000000` means `1.05` USDC per SR).

- Symbol `SR`, name `Spield Standardized Return`, `decimals()` is `7`.
- Mint by `deposit`, burn by `redeem`. There is a per-series deposit cap (`deposit_cap`), which applies to deposits only, never to exits.
- SR is what the PT/SR market pairs PT with, and what the engine takes in `mint_py`.

## PT (Principal Token)

PT is the fixed-income leg: one PT redeems for one unit of USDC at maturity.

- **A classic Stellar asset** with code `SPLDPT` (or a series-specific code such as `SPLDPT9` on testnet), wrapped as a Stellar Asset Contract. A wallet needs a **trustline** to hold it. `@spield/sdk` adds one automatically when needed.
- **A fresh issuer account per series.** That issuer is locked after setup: all signer weights are zero, so no key can ever mint PT. The SAC's admin is the series' Yield contract, so only the engine can mint or burn PT.
- **Not unique by code.** Both mainnet series use `SPLDPT`, under different issuers. Always compare the full `CODE:ISSUER`.

| Series | PT classic asset |
| --- | --- |
| Mainnet Series 2 | `SPLDPT:GBBRKYFRHSDUQ3YQRIFR42GZ4OKFMVKCZN7JYFPESVNSRU3WEE4JPI7Q` |
| Mainnet Series 1 | `SPLDPT:GDNSUOHJIWYXX6HC6ZVDJNLSIBLZMLJYBG7NAN2CRUSXOG4FIDAOH5KN` |

A PT from one series cannot be redeemed through another series' contracts, even when the code matches.
Find the PT address for any series on [Contract addresses](/docs/developers/addresses), or read it from
the Yield contract with `pt_token()`.

<Callout type="warn" title="Compare CODE:ISSUER, never the code alone">
  An integration that matches PT by `SPLDPT` alone will mix up series. Match the issuer too, or
  match the SAC contract address.
</Callout>

## YT (Yield Token)

YT receives the variable yield until maturity.

- **YT is the Yield contract.** There is no YT classic asset and no YT SAC. Use the Yield contract address wherever you need the YT token (`balance`, `transfer`, `approve`).
- **Why:** accrued interest must be settled for both sides before a balance changes, and a SAC cannot run that logic. So the Yield contract is a token with a built-in transfer hook (`before_yt_change`). Every `transfer`, `transfer_from` and `burn` settles both parties first, which is also what makes YT tradable on a market.
- Symbol `YT`, name `Spield Yield Token`, `decimals()` is `7`. No trustline is needed.
- YT stops accruing at expiry. Yield you earned before expiry stays claimable after it.

## USTRY series tokens

A USTRY series uses USTRY (Etherfuse's tokenized US Treasuries) as its asset and has three claim
tokens. USTRY series are **testnet only** today.

| Token | What it is | Trustline needed |
| --- | --- | --- |
| **USTRY** | A classic asset with a SAC. On testnet it is a sandbox asset under a test issuer. | Yes (classic) |
| **sUSTRY** (receipt) | An unsplit deposit receipt. A SEP-41 contract token. | No |
| **PT-USTRY** | The principal claim, in USD face. A SEP-41 contract token. | No |
| **YT-USTRY** | The yield claim, in USD face. A SEP-41 contract token. | No |

- Claim tokens are separate contracts whose balances are read from the series, each with `decimals()` `7`. Moving them does not touch the oracle.
- PT-USTRY and YT-USTRY are denominated in **USD face**, but redemption pays **USTRY units**. USD face is not a principal guarantee.
- USTRY's issuer can freeze balances and claw back tokens. See [Architecture](/docs/developers/architecture#the-ustry-series-family).

## Decimals and fixed-point values

| Kind | Representation | Example |
| --- | --- | --- |
| **Token amounts** (USDC, SR, PT, YT, USTRY, claim tokens) | Integers in base units, **7 decimals** | `10000000` is `1.0` |
| **Rates and prices** (`exchange_rate`, `pt_price`, `implied_apy`, `py_index`) | **12-decimal** fixed point | `1000000000000` is `1.0` |
| **Basis points** (`rate_bps`, `yield_fee_bps`) | Plain integers | `300` is 3.00% |
| **NAV feed prices** (USTRY) | 8 decimals | `100000000` is `$1.00` |

```ts
const toBase = (human: string) => BigInt(Math.round(parseFloat(human) * 1e7)); // '1.5' -> 15000000n
const fromBase = (raw: bigint) => Number(raw) / 1e7;                           // 15000000n -> 1.5
const SCALAR_12 = 1_000_000_000_000n;
// pt_price() of 990000000000n means 0.99 USDC per PT
```

<Callout type="info" title="Use strings for money in JavaScript">
  Floating point can produce more than 7 decimals (`0.1 + 0.2`). `@spield/sdk` accepts human
  amounts as strings (`'10.5'`) and treats a `bigint` as base units. See [the SDK page](/docs/developers/sdk#amounts).
</Callout>

## Discovering addresses at runtime

You do not have to hard-code a series' tokens. Given a series' Yield contract, you can read the rest
from chain:

| Read | Function |
| --- | --- |
| SR address | `sr_token()` on the Yield contract |
| PT address | `pt_token()` on the Yield contract |
| YT address | the Yield contract itself |
| USDC address | `underlying()` on SR |
| Maturity | `expiry()` on the Yield contract |

To discover **which series exist**, use `client.listSeries()` in the SDK, or the signed hosted lists. See
[Contract addresses](/docs/developers/addresses#discovering-series-at-runtime).
